# Contributing to ChatDok open resources

Thank you for your interest. These repositories are small and maintained by the ChatDok team, and contributions are welcome.

## Before you start

- **Bugs and ideas:** open an issue in the relevant repository.
- **Clinical content** (symptom phrases, red flags, test cases): please give a source, such as a guideline or published patient information, and say which language you are adding.
- **Security problems:** do not open an issue. Follow the [security policy](SECURITY.md).

## Never include real patient data

Do not add real conversations, names, contact details or any other information about real people to issues, pull requests or test files. All examples in these repositories are synthetic and must stay that way.

## Pull requests

1. Fork the repository and create a branch.
2. Keep each change focused, and add or update tests where the repository has them.
3. Run the tests (`python -m pytest`) before you open the pull request.
4. Describe what you changed and why.

By contributing, you agree that your contribution is licensed under the license of the repository you contribute to.

## Code of conduct

Be respectful and constructive. Harassment or discrimination of any kind is not tolerated. Report unacceptable behaviour to hello@chatdok.com.
